# D1: Scaffold the football-dashboard repo

Branch: `dash/D1-scaffold` · PR into `main` · PR title: `chore(app): scaffold the read-only observability console`

## Goal

Create the skeleton of a small read-only web console that will show the Football Intelligence backend's logs, traces, errors and crashes. This step builds the project structure, the contract copy, typed domain models, deterministic sample data and CI. No pages beyond a health check yet.

Done when: CI is green, `uv run uvicorn app.main:app` starts locally, `GET /healthz` returns `{"status": "ok", "contract_version": "1.0.0"}`, and every sample event validates against the contract.

## Background you need

- The backend being observed is a FastAPI app (`SumukhaK/football-intelligence-platform`). It will run on Google Cloud Run as service `football-api` and write one JSON log line per event to Cloud Logging, following `guide/telemetry-contract.md` in this repo. Read that file fully before writing code.
- This console reads that telemetry. It never writes to Google Cloud.
- Stack (already decided): Python 3.12, FastAPI, Jinja2 templates, HTMX for partial page updates, Apache ECharts for charts, `uv` for packaging. No Node, no build step for the front end.

## Domain models (`app/domain/models.py`)

Frozen, typed, no behaviour beyond small derived properties:

- `Severity` (StrEnum): DEBUG, INFO, WARNING, ERROR, CRITICAL.
- `TelemetryEvent`: `timestamp: datetime` (UTC aware), `severity`, `event: str | None`, `message`, `request_id: str | None`, `trace_id: str | None`, `span_id: str | None`, `revision: str | None`, `attributes: Mapping[str, object]`. Classmethod `from_log_line(dict)` that reads the contract's field names, including `logging.googleapis.com/trace` (take the part after `/traces/`).
- `TimeWindow`: `start`, `end` (UTC aware, `start < end`, else `ValueError`); classmethod `last_hours(hours, now)`.
- `Span`: `span_id`, `parent_id: str | None`, `name`, `start`, `end`, `attributes`, `events: tuple[SpanEvent, ...]`; property `duration_ms`.
- `SpanEvent`: `name`, `timestamp`, `attributes`.
- `Trace`: `trace_id`, `spans: tuple[Span, ...]`; property `root` (the span with no parent; `ValueError` if none).
- `ErrorGroup`: `group_id`, `exception_type`, `message`, `count`, `first_seen`, `last_seen`, `affected_routes: tuple[str, ...]`.
- `PlatformEvent`: `timestamp`, `kind` (StrEnum: `out_of_memory`, `startup_failed`, `container_exit`, `instance_started`), `revision`, `message`.

## Contract loader (`app/contract.py`)

- `load_contract(path) -> Contract` where `Contract` holds the version, common fields, components, events (required and optional attribute names) and forbidden attribute names.
- `validate_event(contract, line: dict) -> None` raises `ContractError` with a clear message when: a common field is missing; `event` is set but not in the catalogue; a required attribute is missing; an attribute is not in required or optional; an attribute name is in the forbidden list.
- Load once at startup and keep it in `app.state`, not as a module global.

## Sample data (`scripts/make_fixtures.py`)

Generates `fixtures/events.jsonl`: 24 hours of telemetry ending at a fixed time `2026-10-08T18:00:00Z`, seeded with `random.Random(7)`, about 3,000 lines. Every line must pass `validate_event`. It must include, at realistic proportions:

- `http.request` across at least 10 route templates (for example `/v2/fixtures`, `/v2/predict`, `/v2/explain`, `/v2/insights/{team}`, `/v2/teams/{team}/outlook`, `/v2/assistant/chat`, `/v2/auth/sign-in`, `/v2/health`), with statuses 200, 401, 404, 422, 429, 500, 503 and lognormal latencies (chat much slower than the rest).
- At least one of every event in the catalogue except `guardrail.event`.
- Two startup sequences of `component.load` (one revision change), one with `assistant` failed.
- One failed `refresh.run` followed by a `fallback` from `fresh_match_data` to `previous_match_data`, and one successful run.
- `dependency.call` attempts for `ollama_chat` with two `retry` events in one request, and one request that gives up.
- A burst of `ratelimit.rejected` from one `client_ref`.
- A run of failed `auth.event` sign-ins ending in `locked_out`.
- Every line of a request shares its `request_id`; requests that touch the assistant also share a `trace_id`.

Also generate `fixtures/traces.json` (10 traces matching chat requests in the events, with the span names from contract section 4, including a `retry` span event) and `fixtures/error_groups.json` (4 groups) and `fixtures/platform_events.json` (one `out_of_memory`, one `container_exit`, instance starts at each revision change). Running the script twice must produce byte-identical files; test that.

## Tests to write first

- `test_contract.py`: the committed contract loads; version is `1.0.0`; a valid line passes; each failure case above raises `ContractError` with the field name in the message.
- `test_models.py`: `from_log_line` parses a full line and a line with null trace; `TimeWindow` rejects reversed bounds; `Trace.root` finds the root and raises without one; `Span.duration_ms`.

- `test_health.py`: `GET /healthz` returns 200 with the contract version, using `TestClient(create_app(settings))`.
- `test_config.py`: `source="gcp"` without `gcp_project_id` fails validation.

## Repo rules (apply to every file you write)

- Python 3.12, managed with `uv`. Formatting with Black (line length 88), linting with Ruff, types with mypy in strict mode.
- Type annotations on every function signature. No `Any` unless a third-party API forces it, with a comment saying why.
- Every public module, class and function has a one-line docstring.
- No file over 400 lines. No function over 40 lines. Split before you reach either.
- One concern per function. If a function name needs "and", split it.
- No wildcard imports, no mutable default arguments, no global mutable state. Configuration comes only from `app/config.py` (pydantic-settings), never from `os.environ` directly.
- Layering: `app/domain` imports nothing from the app; `app/sources` imports `app/domain`; `app/services` imports `app/domain` and the `TelemetrySource` protocol; `app/routers` import services only. Routers stay thin: no calculations in routes or templates.
- Comments explain why, not what. No commented-out code. No `TODO` without a linked GitHub issue.
- No placeholder code, no fake data paths in production code, no "coming soon" pages. Build the real thing or leave it out.
- The console is read-only. It never writes, deletes or changes anything in Google Cloud.
- Never print or store secrets. `.env` is gitignored; `.env.example` is committed.
- Tests live in `tests/`, mirroring `app/` (`app/services/overview.py` is tested in `tests/services/test_overview.py`). Tests are deterministic: no real clock (inject one), no network, no random without a fixed seed.
- Coverage of at least 80% (`fail_under = 80`).
- Commits use Conventional Commits: `type(scope): description`, lowercase, imperative, no full stop. Types: feat, fix, chore, docs, test, refactor. Scopes: app, sources, ui, ci, deploy, docs, contract.
- Do not add a dependency that this step does not list. If you think one is needed, stop and say why.
